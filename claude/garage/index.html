    Regulatory Lens

    An investment adviser's registration, brochure and 13F holdings, joined into one profile you can search or ask questions of.

    Key figure: 49,574 advisers · 6.75M 13F holdings

    How it fits together

    1. SEC bulk files: ADV, 2A, 13F →
    2. Python ingest →
    3. SQLite, joined on CRD →
    4. FastMCP tools + TinyLlama →
    5. Search workspace
    The problem and the build

    Problem. Adviser details live in three disconnected SEC datasets: Form ADV Part 1 registrations, Part 2A brochure PDFs and quarterly 13F holdings. Pulling them together by hand is slow, and none of it is structured for AI agents.

    How it works. A Python pipeline streams the SEC bulk files into SQLite, joins all three sources on the CRD number, and exposes the result through a seven-tool FastMCP server and a TinyLlama model fine-tuned with QLoRA on the brochures.

    • Astro
    • Python
    • SQLite
    • PostgreSQL
    • FastMCP
    • FastAPI
    • QLoRA / TinyLlama

    Captains View

    An interactive, tactical 2D cricket fielding planner and roster engine with real-time rule enforcement.

    Key figure: Powerplay limit checked on every drop

    How it fits together

    1. 12-player roster →
    2. Drag onto SVG ground →
    3. Role + powerplay check →
    4. Mirror for left-hander
    The problem and the build

    Problem. Captains map fielding plans on scraps of paper or generic boards that know nothing about match format, powerplays, or mirroring the field for a left-handed batter.

    How it works. An SVG ground with pointer-event dragging. A rules check runs on every drop: one bowler, one keeper, eleven on the field, and the powerplay limit on fielders outside the 30-yard circle (measured as distance from the pitch centre).

    • Astro
    • TypeScript
    • Vanilla CSS
    • SVG

    Updated Mar 21, 2026

    Manager Search

    A manager research tool for getting from a name to the filings, holdings, and context I actually want to see.

    Key figure: CRD + CIK entity resolution

    How it fits together

    1. Manager name →
    2. CRD + CIK resolution →
    3. ADV context + 13F holdings →
    4. Grounded summary
    The problem and the build

    Problem. Public filings contain the answers, but it still takes too much manual stitching to turn a manager name into a usable diligence snapshot.

    How it works. A debounced search resolves a firm name to its CRD and CIK, pulls Form ADV context and top 13F holdings, and writes a summary grounded only in those labelled filings.
